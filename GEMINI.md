# Project Guidelines & Restrictions

## Git Command Restriction
- **STRICT PROHIBITION**: Do **NOT** use any `git` commands (e.g., `git commit`, `git push`, `git checkout`, `git add`, `git status`, `git reset`, etc.) in this project.
- All version control, staging, committing, branching, and pushing operations are strictly reserved for the user.
- Any file manipulations, code modifications, or asset updates must be made directly to the workspace files using standard file editing or file generation tools without calling `git` from the command line or scripts.

## Strict Instruction Adherence & No Unsolicited Features
- **STRICT PROHIBITION**: Do **NOT** assume, anticipate, or add features, elements, controls, or logic that the user did not explicitly ask for.
- **Do Exactly What Was Requested**: Stick strictly to the user's explicit instructions without over-engineering or guessing future intent (e.g., do not add video players, extra controls, or decorative logic unless specifically requested).
- **No Uninvited Extras**: Keep code minimal, clean, and focused solely on the user's prompt. If clarification is needed, ask directly rather than implementing assumptions.
